It should be able to reason about situations.

It can challenge you.

It can prioritize.

It combines the capabilities of:

an AI assistant
a digital chief of staff
an AI co-founder
a second brain
a project manager
a strategic advisor
a software agent

The central idea is:

The companion should know the user, understand what they are working toward, remember important context, reason about situations, proactively identify useful actions, and — when permitted — execute those actions through connected tools.

4. PERSISTENT MEMORY ARCHITECTURE

Memory is one of the most important differentiators of the product.

The system should not simply save every conversation into one database and call that “memory.”

Different information serves different purposes.

Types of Memory
4.1 Short-Term / Working Memory

Contains the current immediate context.

Examples:

current conversation
active task
temporary instructions
immediate context
4.2 Episodic Memory

Records things that happened.

For example:

“Yesterday we worked on the portfolio.”

The important components are:

what happened
when it happened
surrounding context
outcome
4.3 Semantic Memory

Stores durable facts.

Examples:

project technologies
business information
known relationships
established facts
important background information
4.4 Procedural Memory

Stores how things are done.

Examples:

deployment procedures
recurring workflows
preferred development processes
standard operating procedures
4.5 Preference Memory

Stores stable user preferences.

Examples:

preferred communication style
preferred tools
preferred workflow
presentation preferences
4.6 Decision Memory

Stores decisions and their reasoning.

Example:

DECISION
Use Flask for the backend.

WHY
Existing familiarity + project requirements.

DATE
[Timestamp]

ALTERNATIVES
Node / other backend approaches

STATUS
Active

Stores:

objectives
desired outcomes
priorities
milestones
progress
deadlines
4.8 Relationship Memory

Stores relationships between:

people
projects
goals
decisions
tools
events
tasks
Memory Quality Requirements

The system should:

Distinguish facts from assumptions.
Record timestamps where appropriate.
Track the source of important memories.
Allow memories to be updated.
Allow memories to be superseded.
Allow memories to become invalid.
Prevent temporary context from automatically becoming permanent.
Preserve the reasoning behind important decisions.
Allow the user to inspect important memories.
Allow the user to correct or delete memories.

26. WHAT MAKES THIS DIFFERENT?
System	Primary Capability	Limitation
Chatbot	Answers questions	Usually lacks durable context and proactive behavior
Second Brain	Stores information	Usually doesn't continuously reason or execute
Task Manager	Tracks tasks	Doesn't deeply understand the user's wider context
Automation Tool	Runs workflows	Usually depends on predefined rules/triggers
AI Agent	Performs actions	May lack a persistent personal model
AI Partner Companion	Understands + remembers + reasons + acts	Designed to combine these capabilities around one persistent user model

The differentiation is therefore not simply “better AI.”

It is the combination of:

Persistence + Context + Reasoning + Proactivity + Action
